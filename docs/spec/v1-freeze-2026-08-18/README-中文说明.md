# 实施包中文说明

这套文件的作用，是让我们在收到开发代码后，不再凭“看起来完成了多少”判断进度，而是逐项验证系统是否真的安全、可运行、可恢复。

## 当前已经锁定的内容

- 第一版只服务公司内部、PUKO、美国英语市场和 B2C 实体产品。
- 员工角色只有 Owner、Operations Admin、Operator。
- 系统只生成、审核和记录任务；外部平台仍由人手动发布。
- 第一版只实现 28 个业务实体组成的最小闭环。
- 外部热点、表现数据、GEO、Learning、Issue 等在最小闭环通过后再补。
- 腾讯云、Docker、PostgreSQL 和对象存储是当前部署方向。
- 生产环境最多丢失 1 小时数据，必须在 4 小时内恢复完整服务。

## 文件怎么用

- `00-DOGFOOD-V1-RUNTIME-FREEZE.md`：告诉开发第一版只能做什么，不能顺手增加什么。
- `01-V1-ACCEPTANCE-MATRIX.md`：规定必须通过的五条测试路径。
- `02-DELIVERY-EVIDENCE-AND-DEPLOYMENT-GATES.md`：规定代码、Staging、备份恢复和正式上线的门槛。
- `03-POST-CLOSURE-BACKLOG.md`：最小闭环通过以后，下一步补什么。
- `04-DECISION-LOG-2026-08-18.md`：记录本次会议的决定、修正和未确认事项。
- `05-CODE-DELIVERY-MAPPING-TEMPLATE.md`：代码到手后逐个核对表、接口和测试。

## 我们接下来做什么

1. 等开发发送固定版本的源码，而不是只接收截图或完成度说明。
2. 在干净环境中重现安装、数据库迁移、初始化、启动和测试。
3. 填写代码映射表，重新计算真实完成度。
4. 只修复最小闭环缺口，不增加 Blueprint 功能。
5. 部署到独立 Staging，依次运行正常、阻塞、返工、门禁失败和幂等/权限/并发五条路径。
6. 完成备份恢复演练后，才决定是否可以正式上线。

## 你需要关注的判断

- “代码完成 80%”目前只是开发自报，不是已验证进度。
- 8 月 30 日是目标日期，不是强制上线日期。
- 五条路径、权限、安全、备份和恢复任何一项没有通过，都应该延期，而不是带问题上线。
- 真实密码、Cookie、API Key、私钥和数据库连接信息不要发给 Codex、DeepSeek 或放进普通文档。
